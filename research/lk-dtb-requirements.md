# What the Cosmo's LK demands of a kernel image (reverse-engineered)

Source: static decompilation of `collected/boot-backup/lk.img` (MediaTek LK,
`k71v1_64_bsp-cf6de92-20200706`, ARM32/Thumb-2, load base `0x56000000`) with Ghidra,
2026-10-06. Function addresses below are in that binary. **Confirmed on hardware**: the
first image built to these rules booted, and every PennyOS image since is checked
against them by `tools/check-lk-dtb.py` before it is packaged.

## Why every mainline image so far boot-looped

LK never jumped to our kernel. It hit an `ASSERT`/`while(1)` while preparing the device
tree, which resets the phone (→ the `0e8d:2000` preloader blip we kept seeing). The old
conclusion "kernel never reaches USB init" was true but for a reason upstream of the
kernel. Kernel size, packaging and load addresses were all fine.

The affenull2345 DTB violates four independent rules, any one of which is fatal:

| # | Rule | Where in LK | Failure mode |
|---|---|---|---|
| 1 | The vendor **`dtbo` partition overlay is always applied** to the DTB appended to the kernel. `/__symbols__` must resolve every label in the overlay's `__fixups__` (61 labels: `pio`, `i2c0`‥`i2c11`, `scp`, `odm`, `gpio`, `mt6370_pmu`, …). | `FUN_5602c200` (`fdt_op.c`), libufdt | `ufdt_apply_overlay() failed!` → assert |
| 2 | **`/chosen/bootargs` must exist.** | `FUN_5602bcdc` | assert |
| 3 | A node with **`compatible = "mediatek,scp"`** must exist (`platform_fdt_scp`). `mediatek,mt8183-scp` does not match. | `FUN_56021428` via `platform_atag_append` | assert `mt_boot.c:0x394` |
| 4 | **No static `/reserved-memory` child with `reg` may overlap a region LK reserved itself** (ATF `0x54600000`, TEE `0xedb00000`, SSPM, SPM, SCP, modem, framebuffer, dramc). LK appends those itself as `mblock-N-*` nodes. | `reserved_memory_conflict_check`, `FUN_5603afa4` | `fatal error keep while (1)` |

Also required (already satisfied): `/memory`, `/chosen`, `/reserved-memory` exist; boot
header `tags_addr == 0x54000000`, `ramdisk_addr == 0x55000000`, ramdisk ≤ 16 MiB; kernel
load address 512 KiB-aligned; `bootopt=64…` in the **boot.img header** cmdline; merged DTB
≤ 512 KiB; decompressed kernel ≤ 200 MiB.

## Other facts worth knowing

- **DTB discovery:** LK reads the last 512 KiB of the kernel blob and scans *backwards*
  for `d00dfeed`. Append exactly one DTB, last.
- **Final cmdline** = DTB `/chosen/bootargs` + boot.img header cmdline + LK's own
  (`maxcpus=8 … root=/dev/dm-0 … androidboot.*`). So real kernel args go in the DTB.
- LK writes `/memory/reg`, a 22 KiB `mblock_info` blob, `linux,initrd-start/end`
  (1-cell), `atag,*` props, and the `mblock-N-*` reserved-memory nodes into our tree.
- LK also *consumes* the merged tree for itself: GPIO defaults from
  `/gpio@10005000:gpio_init_default`, LED/backlight config from `/odm/led@N`, SCP
  on/off from the `mediatek,scp` node's `status`. All of those come from the overlay.
- If `/reserved-memory/zmc-default` exists (the overlay adds it), LK creates a ~4 GiB
  `zone-movable-cma-memory` node. Harmless on vendor 4.4, would eat RAM on mainline.
- Compressed kernel is staged at `0x56900000`, gunzipped to `0x40080000`.
- `text_offset = 0` at `0x40080000` is not 2 MiB-aligned; mainline tolerates it with
  `CONFIG_RELOCATABLE=y` (prints a `[Firmware Bug]` line). Verified in QEMU.

## How we satisfy LK without letting vendor DT content near mainline nodes

`devicetree/mt6771-mtk-lk-compat.dtsi` (generated by `tools/gen-lk-compat-dtsi.py` from
the overlay itself, included last in the board DTS):

- a hand-written `/__symbols__` that maps each vendor label to an inert node under
  `/mtk-lk-sink` (no `compatible`, so the kernel never populates it) — except `chosen`,
  `odm` and `gpio`, which get vendor-shaped homes because LK reads them back by path;
- the sink `scp` node carries `compatible = "mediatek,scp"`, `status = "disabled"`;
- `/delete-node/` for the static ATF/SPM/SSPM/SCP/dramc/TEE reservations;
- `reserved_memory` points at the sink, so `zmc-default` never reaches the real node.

`tools/check-lk-dtb.py` replays rules 1–4 offline (using `fdtoverlay`, i.e. libfdt rather
than LK's libufdt) and `tools/mkboot.sh` refuses to package a DTB that fails it.

## Black box for whatever happens next

`devicetree/pennyos-debug.dtsi` adds a `ramoops` node with the **same region and zone
layout as the vendor kernel** (`0xe0000@0x54410000`, 4K records, 256K console, 4K ftrace,
64K pmsg, no ECC). After a *warm* reset into rooted Android, the mainline console log is
at `/sys/fs/pstore/console-ramoops*` → `tools/read-lastboot.sh`. Layout verified in QEMU
(console zone header `DBGC` found at `base + 0x8f000`, full log inside).

It also adds a `simple-framebuffer` on LK's scanout buffer (`0x7df70000`, 1080×2160,
stride 4352, a8r8g8b8) for an on-screen console. Unverified: if the panel runs in DSI
command mode nothing will refresh it.

The debug initramfs dumps state to `/dev/kmsg` and, if no USB host configures the gadget
within 90 s, **reboots in software** so the log survives.
