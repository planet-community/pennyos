# What works, and by what means

State of PennyOS (mainline Linux 6.4 + Debian 13) on the Planet Cosmo Communicator (MT6771,
Solomon SSD2092 panel variant, Japanese keyboard), as of 2026-10-29. Everything here
was checked on one physical phone.

**How it works** uses these terms:

- **mainline driver**: a driver that is in upstream Linux, used as is.
- **mainline + patch**: an upstream driver with a small patch from `kernel/patches/`.
- **own driver**: written for this project, in `kernel/drivers/`.
- **vendor port**: MediaTek's out-of-tree source, built against 6.4 with our changes
  (`kernel/connectivity/`).
- **binary blob**: closed firmware or data copied from the phone's Android install.
  It is not in this repo; `tools/collect-radio-blobs.sh` gathers it from your phone.
- **bootloader**: set up by the stock LK bootloader and left alone.
- **userspace**: a script or setting in the root filesystem (`tools/rootfs/`).

The kernel tree itself is affenull2345's `mt6771` branch (Linux 6.4), which adds the
MT6771 and Cosmo device trees on top of upstream.

## Works

| Component | How it works | Notes |
|---|---|---|
| Boot through the stock, locked bootloader | Android boot image in a multiboot slot; device tree compatibility layer generated by `tools/gen-lk-compat-dtsi.py` | LK's requirements were reverse-engineered: [lk-dtb-requirements](../research/lk-dtb-requirements.md). Android is untouched. |
| Root filesystem on internal eMMC | mainline driver (mtk-sd); Debian 13 built with debootstrap | Installed to the `linux` partition. |
| SD card | mainline driver (mtk-sd) | |
| Display | mainline driver (mediatek-drm, DSI) + patches 0005/0006; **own driver** for the panel (`panel-planet-ssd2092.c`) | Panel reset, init and suspend sequences come from Planet's published 4.4 kernel source. Powers off and on cleanly. |
| Backlight | mainline driver (mt6370-backlight) | Maximum capped to what Android uses. |
| Keyboard backlight | mainline drivers (pwm-mediatek, leds-pwm), `devicetree/pennyos-kbd-backlight.dtsi`; **userspace** `penny-kbd-light`, `penny-kbd-auto` | SoC PWM channel A on GPIO90, found in Planet's `aw9524_key.c` (despite the name, not the expander). Fn+Shift+N / Fn+Shift+B step through off / 25 / 50 / 100 %. Works on the phone. Automatic by default (`penny-kbd-auto`, Settings > Keyboard light): typing lights it at the last level set with the keys, and it goes off 15 s after the last key (5 s to 5 min, or automatic off); switched off by hand it stays off while typing; closing the lid switches it off and keys are ignored while closed. The sleep hook switches it off as soon as a sleep starts (the LED core alone only does so at the very end, seconds after the lid closed) and restores the level on wake if the lid is open. |
| GPU (Mali-G72, GLES 3.1) | mainline driver (Panfrost) + Mesa | |
| Touchscreen | **own driver** (`ssd20xx.c`) | The chip's touch firmware lives in its own flash; nothing is loaded from disk. |
| Keyboard | matrix driver from the kernel tree (`gpio-fastmatrix-keyboard`, not upstream); **userspace** xkb layout (`tools/rootfs/files/xkb/cosmo`) for the Fn layer | Only the Japanese layout has a variant. Fn types the printed legends; the planet key is the desktop modifier. Fast typing dropped keys (a press during a scan was never reported); two kernel patches (0009, 0010) fix that. Some two-key combinations lost a key or produced a phantom one (Fn+V lost the V, Ctrl+O gave 0); the matrix itself reads them correctly, the cause was the AW9523 driver's interrupt masking putting the whole register map in cache-only mode under a running scan. Patch 0012 masks interrupts without that, 0013 redoes a scan whose row read fails. Checked on the phone: Fn+V, Fn+C held with repeats, Ctrl+O. |
| Power key (Esc) | mainline driver (mtk-pmic-keys) + device tree settings | Reported as Esc; long press powers off. |
| Wi-Fi (2.4 and 5 GHz, WPA2) | **vendor port** (MediaTek WMT + gen3 wlan driver, ~790 files) + **binary blobs** (MT6631 firmware patch, per-phone calibration from NVRAM) + own daemon `penny-wmtd` | Comes up at boot. About 10-23 Mbit/s measured. Joined from the bar: tapping the Wi-Fi icon drops down signal, address, disconnect and forget, or the networks in range or `penny-wifi-connect` in a terminal. Personal (password) and open networks only; enterprise and WEP are refused. The new menu is not yet tested on the phone. [wifi-scoping](../research/wifi-scoping.md) |
| USB device mode: serial console and Ethernet | mainline driver (mtu3) + patch 0002, g_cdc gadget | SSH over the cable. The patch forces "VBUS present", so unplugging is not detected. |
| Charging | mainline driver (mt6370-charger) + **userspace** `penny-charge-setup` | The script sets the minimum input voltage and follows the USB-C current; without it the phone does not charge from 5 V. Charge voltage is a conservative 4.2 V. |
| Battery level (fuel gauge) | **own driver** (`cosmo_fg.c`: MT6358 coulomb counter + MT6370 cell voltage), `devicetree/pennyos-battery.dtsi` | Percentage, charge, voltage and status in `cosmo-battery`, read by the bar and UPower (which powers off at 2 %). Starts from the open-circuit voltage at boot, counts charge from then on, snaps to 100 % when the charger finishes. Battery data from the vendor profile, 25 C table only (no battery temperature yet); 100 % = 4.2 V, 0 % = 3.4 V, 3658 mAh between. Counter checked against the measured current on the phone; the percentage over a full discharge is not yet checked. |
| SoC temperature and thermal protection | mainline driver (auxadc_thermal, MT8183 variant) + **userspace** `penny-thermal` | `cpu-thermal` zone; the kernel powers off at 115 C. There is no CPU frequency scaling and cores cannot be taken offline, so `penny-thermal` instead confines apps (`user.slice`) to fewer, then only little, cores and caps the GPU clock from 75 C. Levels checked with emulated temperatures; never yet reached for real. |
| USB-C port controller | mainline driver (tcpci-mt6370) | Used for the advertised current. |
| Real-time clock | mainline driver (rtc-mt6397) | Also the wake-up timer for sleep. |
| Watchdog and reboot | mainline driver (mtk-wdt) + patch 0001 | The patch takes over the watchdog as LK leaves it; without it `reboot` hangs. |
| Regulators (MT6358) | mainline driver + patch 0003 | The patch keeps unclaimed regulators on. |
| Unused clocks and power domains switched off | mainline drivers | Display, USB, Wi-Fi and GPU still work with this on. |
| Screen off | own panel driver + **userspace** `penny-screen` | Fn+Esc, or after 3 minutes idle. |
| Sleep (s2idle) | mainline + **userspace** sleep hook and `penny-sleep` | Sleeps and wakes on a timer or the lid. Saves only about 20 mA over screen-off so far. See caveats below. |
| Lid sensor | mainline driver (gpio-keys), `devicetree/pennyos-lid-keys.dtsi`, logind config | Closing the lid locks and sleeps, opening it wakes. |
| Notification LEDs | mainline drivers (gpio-leds on the AW9523 expander, leds-mt6370-rgb), `devicetree/pennyos-leds.dtsi` | Every LED is in `/sys/class/leds`, switchable by the `video` group: Caps Lock key, above the outer display, both sides of and below the fingerprint sensor. LED names do not always match the colour seen; the map is in [leds-and-sensors](../research/leds-and-sensors.md). Nothing drives them yet (no charging or notification light). |
| Camera flash as a torch | mainline driver (leds-mt6370-flash) | `white:flash-1` / `white:flash-2`, two channels into one LED. No camera to fire it. |
| Light and proximity sensor | mainline driver (stk3310), `devicetree/pennyos-sensors.dtsi` | STK3311-X on i2c1. Lux and raw proximity in IIO. Not yet used for automatic brightness or blanking the screen in calls. |
| Speakers | mainline drivers (mt8183-afe-pcm, mt6358 codec) + **own driver** for the sound card (`cosmo-sound.c`) + **userspace**: `penny-sound-setup` (udev, sets the mixer routing), `/etc/asound.conf` (software volume and dmix), `penny-volume` (keys) | Both speakers play from any ALSA program (`default` device). The codec's line out L feeds two amplifiers enabled on GPIO153/111; the card switches them on only during playback, with the 3-pulse mode select from Planet's kernel. Line out is powered through the codec's headphone mux in "LoudSPK Playback"; the plain line-out path leaves its supplies off. The codec's `Lineout Volume` only spans -10 to +8 dB (patch 0011 makes it read back correctly while nothing plays), so it stays at full and the volume is an ALSA software control, `Master` (-50 to 0 dB), in the default device (`/etc/asound.conf`), which also mixes several programs at once (dmix). Fn+V / Fn+C step it in 10 % on ALSA's perceptual scale, Fn+X mutes, with an on-screen bar (`penny-volume`); starts at 40 %, kept across reboots by alsactl. No sound server (PipeWire) yet; programs that open the hardware device directly bypass the volume and block the others. There is no RT5509 amplifier chip on this phone, although the vendor kernel config enables that driver. |
| Diagnostics app | **userspace** `penny-diag` | Switch each LED on and off; live sensor, temperature, battery and charger values. |
| Low memory | zram (module, `CONFIG_ZRAM`) + 1 GiB swap file + earlyoom + **userspace** `penny-memwatch`; config in `tools/rootfs/files/memory/` | Swap is zram first (zstd, half of RAM, priority 100), then `/swapfile` on the eMMC (priority 10, created on first boot). `penny-memwatch` notices thrashing from the swap-in rate (the kernel has no PSI) and pops up "Close <app> (size)" / "Not now"; an app from the desktop is measured and closed as a whole (its systemd scope), a program in a terminal on its own. Tested with a program growing past RAM while using all of its memory: the popup came about 3 s into thrashing, and closing freed it within 2 s. Left alone, that thrashing goes on for minutes with stalls of up to 10 s, since earlyoom (the backstop) only acts once memory and swap are both nearly gone; the kernel OOM killer ends a fast runaway within about a second. |
| Desktop | niri (built from a pinned commit), waybar, fuzzel (built from a pinned release: Debian's 1.12 ignores touch), mako, foot | `tools/rootfs/files/theme/` |
| Login screen | greetd + gtkgreet inside a bare niri, **userspace** config | `tools/rootfs/files/greetd/` |

## Partly works

| Component | State | What is missing |
|---|---|---|
| Sleep | s2idle only. USB is dropped and Wi-Fi switched off for the duration, both restored on wake; the keyboard driver is restarted on wake because it does not resume by itself. The session (lock screen included) is usable about 0.1 s after waking: the Wi-Fi restore runs as a separate job, since systemd keeps the session frozen until the sleep hooks return (it used to take about 6 s). Wi-Fi reconnects about 5 s after waking. | "deep" sleep goes through firmware (PSCI) calls that do not work here. Wake sources tested: timer and lid. |
| CPU power management | All eight cores run at the frequency the bootloader left (1.1 / 1.2 GHz), idling in WFI. | Frequency scaling is disabled in the kernel tree as broken. Idle states and core hotplug through PSCI crash or do not return: [power.md](../research/power.md) |
| Power off | Works from the menu and by long press. | With a charger attached the phone probably starts again into Android's charging screen (not verified). |
| Microphone | mainline drivers (mt8183-afe-pcm for the SoC audio block, mt6358 codec) + **own driver** for the sound card (`cosmo-sound.c`) | Records from the built-in microphones (codec inputs AIN0 and AIN2; AIN1 carries nothing with no headset plugged in). The main microphone is routed at boot and is the default capture device, so any program can record. Gain and the choice between the two microphones are not tuned. |
| Voice typing (Fn+Space) | **userspace** `penny-dictate`: whisper.cpp (built from a pinned commit) with the tiny English model, typed with wtype | Worked once on the phone; a second dictation in the same session did not, cause not yet found. English only. About 8 s for an 11 s clip. |
| Bluetooth | **vendor port** driver + own bridge daemon `penny-btd`: BlueZ sees the controller and every command succeeds. | It receives nothing (scans find no devices). Not started at boot. [bluetooth.md](../research/bluetooth.md) |
| USB | Device mode only. Networking and serial come back after sleep. | Host mode (OTG) is not set up. |

## Does not work

| Component | Why |
|---|---|
| Modem: calls, SMS, mobile data | No driver. The modem is held powered off. |
| Earpiece, headphone jack | Not started. In Planet's kernel the earpiece is the codec's receiver output with GPIO108 high; GPIO108/107 also switch the jack. Both GPIOs are only raw mixer switches in `cosmo-sound.c`. |
| Headset microphone and button | Not started. |
| Bluetooth audio | Not started. |
| Cameras | Not started. |
| GPS, FM radio | Part of the same combo chip as Wi-Fi; not started. |
| Cover display and its side button | Driven by a separate microcontroller; not started. |
| Fingerprint reader | Not started. |
| Accelerometer and gyroscope | Nothing answers on SPI1, where the vendor tree puts it; Android reaches it through the SCP sensor hub. [leds-and-sensors](../research/leds-and-sensors.md) |
| Magnetometer (AF6133E) | Answers on i2c1 0x0c; no mainline driver. |
| Barometer | Nothing answers at the vendor tree's address. |
| NFC | Not started. |
| Battery temperature | The MT6370 ADC has the thermistor input (`ts_bat`); its conversion to degrees is not worked out. The gauge then could use the vendor tables for other temperatures. |
| Novatek NT36672 panel variant | No panel entry with an init sequence and no touch driver. Such units boot with the bootloader's picture but this repo does not describe them. |
| Keyboard layouts other than Japanese | The key codes work; the Fn layer needs an xkb variant per layout. |

## Known rough edges

- After a watchdog or long-press reset the screen can stay black until a cold start.
- A display state the kernel did not set up survives a warm reboot; a cold start
  (power fully off) clears it.
- `RF Stat WF_Sx LPAON_LPCR Fail!` is logged when Wi-Fi powers on; no effect seen.
- SSH is key-only; the default console password is `cosmo`. Change it (`penny-setup`).
